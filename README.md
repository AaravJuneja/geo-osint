# Geo-OSINT Challenge Template

A reusable template for building location-guessing challenges around a 360° panorama. Players explore the panorama, figure out where it is, and submit coordinates to unlock an answer. Works for CTFs, treasure hunts, orientation games, or any "guess this place" exercise.

The frontend serves a Pannellum panorama; a Cloudflare Pages Function checks each guess against a hidden target coordinate and reveals the answer when the guess is close enough. The target coordinates and answer never reach the browser.

## How It Works

- Static viewer files in `public/`
- Pannellum multires panorama assets in `public/assets/panorama/` (generated by `scripts/build_panorama.py`)
- Coordinate submission form in `public/assets/app.js`
- Backend validator in `functions/api/guess.js` (Pages Function, route `/api/guess`)
- Cloudflare headers in `public/_headers`

## Making a Challenge

### 1. Pick a Street View panorama

Open Google Maps (or Google Street View) on a place you like and copy the panorama ID from the URL. It is the part after `!1s` and before `!2e`. Example URL: `https://www.google.com/maps/...!1s2Im_M7yjJ1OS5HUFvCI8hg!2e0!4m2!3m1!1s0x0...` has panoid `2Im_M7yjJ1OS5HUFvCI8hg`.

### 2. Generate the panorama assets

Requirements: Python 3 and the pinned build dependencies in `requirements.txt`.

```bash
python3 -m pip install -r requirements.txt
```

```bash
python3 scripts/build_panorama.py
```

The script prompts for the panorama ID, downloads the Google Street View tiles, stitches them, and writes Pannellum multires assets to `public/assets/panorama/`. You can set the starting view with `--yaw` and `--pitch` (degrees), and change the output location with `--out`.

| Flag | Description |
| --- | --- |
| `--yaw` | Initial horizontal view in degrees (default `0`) |
| `--pitch` | Initial vertical view in degrees (default `0`) |
| `--out` | Output directory (default `public/assets/panorama`) |

Street View source tiles are cached in `.cache/` (git-ignored) so re-running for the same panorama is fast. The generated `config.json` embeds the correct `basePath`, so `--out` can point at a different folder if you want to host several panoramas.

### 3. Set the target and answer

Configure via environment variables (never commit real secrets; the repo's `.env` is git-ignored):

| Variable | Required | Description |
| --- | --- | --- |
| `CHALLENGE_TARGET_LAT` | yes | Target latitude |
| `CHALLENGE_TARGET_LNG` | yes | Target longitude |
| `CHALLENGE_ANSWER` | yes | What gets revealed on a correct guess (flag, phrase, next-clue URL, ...) |
| `CHALLENGE_RADIUS_METERS` | no | How close a guess must be, in meters (default `25`) |
| `CHALLENGE_SUCCESS_MESSAGE` | no | Message shown with the answer (defaults to the answer itself) |

Copy `.env.example` to `.env` locally and fill it in. For production, set these in your hosting platform instead.

### 4. Deploy

This template is set up for Cloudflare Pages (Pages + Functions via the CF CLI):

- Static directory: `public`
- Functions directory: `functions` (`functions/api/guess.js` serves `/api/guess`)
- Add the `CHALLENGE_*` environment variables in Pages Settings → Variables (or `bunx wrangler pages secret` for the answer)
- `bun run dev` (`bunx wrangler pages dev public`) for local preview, `bun run deploy` (`bunx wrangler pages deploy public`) to publish
- `bunx wrangler login` once to authenticate the CF CLI

For a plain static host that cannot run `functions/api/guess.js`, the viewer still works but submissions won't be validated.

## Challenge Builder UI

Open the viewer and click **build challenge** (bottom-left) to use the built-in setup helper. Fill in the challenge details and it will generate:

- The `python3 scripts/build_panorama.py ...` command with your selected yaw/pitch/output flags
- A ready-to-copy `CHALLENGE_*` environment variable block
- A short checklist for local validation and deployment

The builder keeps sensitive values in your browser session only and does not send them to the backend.

## Customising the Frontend

- **Panorama path**: set `data-config` on the `#panorama` element in `public/index.html` to point at a different `config.json`.
- **Page title**: change the `<title>` in `public/index.html`.
- **Map tiles**: the guess map uses OpenStreetMap tiles by default (see `public/assets/app.js`). Swap the tile layer URL if you prefer another provider, and update `img-src` in `public/_headers`'s Content Security Policy if the domain changes.

## Regenerating Assets

```bash
python3 scripts/build_panorama.py
```

Enter the panorama ID when prompted. The script wipes the output directory and regenerates all tiles, the fallback faces, `preview.jpg`, and `config.json`.

## Security Notes

- Target coordinates and the answer live only in server environment variables, never in `public/`.
- The panorama ID is never stored in the repo or served to the browser. The build script asks for it and discards it, so the deployed files contain no panoid.
- Generated assets are metadata-free: the build pipeline re-encodes every image and strips any EXIF/GPS that the raw Street View tiles may carry, so players cannot pull coordinates out of the image files.
- Raw downloaded tiles are cached only in `.cache/` (git-ignored, outside `public/`, and not served). Only the cleaned output under `public/assets/panorama/` is deployed.
- `public/_headers` sets strict headers: `noindex`, no framing, no referrer, and a Content Security Policy that only allows the CDNs in use.
- The panorama itself is public by design (players need it to play), so reverse-image searching the imagery is possible — that is inherent to geo-OSINT and is the puzzle itself.
- The validator returns only a binary pass/fail with no distance feedback, so brute-forcing coordinates is impractical. If you need stronger protection for a graded event, add rate limiting or gate the answer behind your own scoring host.
